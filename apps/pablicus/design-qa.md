# Ordered message composer design QA

Reference: the user-supplied two-panel Pablicus concept, followed by the more
specific requirement to insert media within one message and keep recording
independent of editing. Existing Pablicus colors, identity and navigation are
retained. This slice does not reproduce the Focus/shared-canvas concept in full.

Verified in isolated built-app Chromium fixtures at a 440 px mobile width:

- Text and attachments retain insertion order within the growing editor.
- Fullscreen remains scrollable; attachment and microphone controls are usable.
- Receiver content is one purple bubble with inline image and ordered media
  cards. One send status belongs to the complete message.
- Media card error text overlays reserved space, avoiding virtual-list height
  changes. Offscreen measuring copies do not load media.
- The same app pipeline retains original file bytes across reload and retries.

Reproducible screenshots are generated by `tests/rich_message_integration.py`
as `rich-integration-<engine>-composed-top.png`, `-composed-bottom.png` and
`-sent-bubble.png` under the test evidence directory. Test photos use the local
product icon. Mock audio/video fixtures prove transport, not media decoding.

The interactive cloud preview could not start in its restricted runtime;
visual evidence therefore comes from the explicit isolated application test.
Physical Safari/PWA recording, system file-picker interruptions, keyboard
ergonomics and actual two-phone receipt remain device acceptance checks.
