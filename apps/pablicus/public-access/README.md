# Pablicus — публичный вход без нового пароля

Статус: **подготовленная часть, не опубликована и не подключена к рабочему серверу**.

Последнее решение владельца от 8 сентября 2026: **от SMS отказаться; подключать вход через Google и другие почтовые аккаунты, обязательно Яндекс**. Основной текущий кандидат — OAuth, не SMS. Список: Google, Яндекс, Mail.ru, Outlook/Hotmail. Исторические SMS-модули ниже сохранены как прежняя работа, в сборку и интерфейс не подключаются.

## Текущий кандидат OAuth

- `src/oauth-login.js`: четыре провайдера, настоящий `signInWithOAuth`, S256 PKCE, переход в том же окне после проверки адреса сервера, отказ при неподключённом провайдере. Пароль почты не запрашивается.
- `src/oauth-session.js`: очистка адреса до создания SDK, единственный обмен кода, серверная проверка пользователя, понятная отмена/ошибка, отказ при отсутствии подтверждения в другом браузере.
- Вход встроен в основную сборку. `src/auth-config.js` содержит только публичные флаги готовности; все выключены. Пока серверы не подключены, опубликованный интерфейс не заменяется неработающими кнопками. В проверяемой сборке список показывается с тестовой конфигурацией.
- Запрос восстановления прежнего пароля выполняет отдельный клиент без постоянного хранилища и без PKCE: письмо по-прежнему можно открыть в другом окне. Существующее хранилище сессии приложения сохранено.
- `OAUTH_PROVIDERS.md`: требования регистрации приложений у провайдеров и точные callback-адреса. Для Яндекса подготовлен отдельный UserInfo-адаптер; для Mail.ru активация остаётся заблокированной до проверки текущего процесса регистрации Mail ID.
- `.github/workflows/pablicus-oauth-candidate.yml`: проверки кандидата с подменёнными ответами Auth; не имеет шага публикации или доступа к реальным аккаунтам.

Настоящие регистрации приложений у Google/Яндекса/Mail.ru/Microsoft, выдача Client ID/Secret, настройка Auth и реальный вход пользователя ещё не выполнены. Разрешение на публичный доступ уже дано владельцем. Ограничения записи не обходить.

Решение владельца от 8 сентября 2026: регистрация общедоступная, без ручного одобрения; вход через существующую почтовую идентичность и через номер/SMS, без обязательного отдельного пароля. Это решение заменяет прежнее требование закрытого теста. Текущая опубликованная RC5 пока остаётся прежней: её серверные ограничения в этой работе не изменены.

## Что готово

- `sms-form.html`: номер с кодом страны → запрос SMS → шесть цифр → «Войти»; номер можно исправить.
- `sms-login.js`: запрос и проверка через настоящий Supabase Auth API, обработка отказов/неверного кода, задержка повторного запроса, проверка подтверждённого номера на сервере и передача сессии штатной проверке профиля приложения. Нет создания пароля, чтения почты, административных ключей или самостоятельного одобрения профиля.
- `sms-login.test.js`: шесть проверок с неизменённым SDK из репозитория и полностью подменёнными HTTP-ответами. Реальные номера не используются, SMS не отправляются. Проверяется успешный вход, некорректные данные, отключённый сервис, отказ отправки, истечение кода, смена номера, другая/неподтверждённая идентичность и отказ приложения в доступе.
- `SERVER_SETUP.md`: наблюдённая схема и конкретный проект исправления создания пользователей только с номером телефона, уникальных usernames и одноразовой активации после подтверждения. SQL не выполнен и пока не проверен исполнением на тестовой базе.

Проверка: `node --test apps/pablicus/public-access/sms-login.test.js` — 6/6 PASS. Синтаксис JavaScript проверен. Проверка в настоящем мобильном интерфейсе и получение реального SMS ещё не выполнены.

## Подключение

После серверного изменения и проверки SMS-провайдера встроить HTML-фрагмент в основной экран, включить JS в build/SW и подключить к существующему клиенту `sb`:

```js
PablicusSmsLogin.mount({
  element: smsSection,
  client: sb,
  authenticate,
  enabled: true,
  getCaptchaToken: () => currentCaptchaToken,
});
```

`smsSection` и `currentCaptchaToken` — ссылки, которые должен предоставить экран приложения. Этот фрагмент показывает контракт интеграции, а не готовую интеграцию в RC5. Флаг `enabled` по умолчанию false: он не включает провайдера на сервере. Перед публикацией нужны реальные подтверждённые серверные настройки, создание нового профиля, испытание получения SMS и браузерная проверка формы. Клиентский таймер не заменяет серверные ограничения отправок. Код подтверждения очищается после отправки и при уходе со страницы; он не сохраняется в localStorage, URL или отчётах.

## Реальные ограничения доступа

Текущее подключение: `current_user=supabase_read_only_user`, `transaction_read_only=on`, права CREATE в public и UPDATE profiles/auth.users отсутствуют. Не запускать подготовленный SQL через обход этих ограничений. На последних скриншотах владельца Phone выключен, поля Twilio пустые. Позже владелец отменил SMS. Его собственный вход в Supabase на iPhone не создаёт авторизованную сессию в браузере помощника.

Для продолжения нужны штатный доступ на запись к базе и настройкам Auth, настроенный сервис отправки SMS и его подтверждённая доставка. Выбор/оплата провайдера и создание серверных секретов в этой работе не выполнялись. Включение общедоступной регистрации уже разрешено владельцем; повторное разрешение на сам продуктовый переход не требуется.

## Почтовый вход

Универсальная проверка пароля от произвольной почты в форме Pablicus не реализована: почтовые сервисы не предоставляют общего интерфейса проверки такого пароля. Нельзя переименовывать поле пароля Pablicus в «пароль от почты» и отправлять его в существующий password grant.

Определение сервиса по домену может убрать выбор провайдера с экрана, но подтверждение всё равно выполняет сам подключённый почтовый сервис. Неизвестные/корпоративные домены нельзя автоматически приписывать к провайдеру по догадке. [Официальный сценарий Яндекс ID](https://yandex.ru/dev/id/doc/ru/concepts/ya-oauth-intro) и [OAuth в Supabase](https://supabase.com/docs/guides/auth/social-login) описывают именно подтверждение у провайдера без передачи его пароля приложению.

Клиент OAuth теперь встроен в кандидат; провайдеры на сервере ещё не подключены. Ни публичная регистрация, ни SMS, ни почтовый OAuth пока не объявляются работающими на опубликованном сайте.
