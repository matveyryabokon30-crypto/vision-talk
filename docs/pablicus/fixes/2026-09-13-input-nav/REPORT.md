# Исправление действующего Пабликуса: ввод и нижняя навигация

## Поручение владельца

Вернуться к существующему приложению. Исправить уход чата вверх при Enter, перенести «Боты» в нижнюю плашку, добавить пиктограмму AI-агента, опубликовать обновление и записать изменения в репозиторий. Дополнительное решение владельца: **AI-агент пока неактивен**. Другие изменения запрещены. Отвергнутый отдельный прототип и его редизайн в этот выпуск не входят.

Рабочая база: `bf90a64`. Действующая публикация до исправления: `0e953322eac69e6f3e79458ac32323b564acaf55`, ветка `publish/pablicus-2b-20260912`. Runtime в рабочей базе совпадал с публикацией. Разрешение на данный patch и deployment дано непосредственно новым поручением; прежняя остановка forensic-этапа им заменена только в указанной границе.

## Причина и исправление

На настоящем entrypoint с синтетической сетью воспроизведён дефект в Chrome и WebKit. После 30 Enter textarea вырос до 744 px, внешний editor имел высоту 200 px и `overflow:visible`. Нативное удержание курсора прокручивало контейнер `#app`, хотя у него стоял `overflow:hidden`: в Chrome заголовок оказался на y = −481 px. На снимке WebKit интерфейс целиком ушёл из видимой области. Это конкретное воспроизведение механизма; оно не является доступом к состоянию телефона владельца.

Исправлена существующая цепочка, без замены rich-editor или формата данных:

- Обычный textarea ограничен высотой 144 px и 28% видимого viewport, с внутренней прокруткой длинного текста. Родитель editor также получает ограниченную высоту и собственную прокрутку.
- Внешний контейнер чата использует `overflow:clip`: нативное перемещение к курсору больше не прокручивает весь экран. Лента и редактор сохраняют собственные scroll-контейнеры. Полноэкранный режим остаётся явным действием кнопки.
- Существующая кнопка `openBots` перенесена из header в нижнюю навигацию. Она вызывает прежний route `section:bots / screen:bots` через единственного владельца навигации.
- Нижний ряд: Чаты / Дела / Боты / AI-агент / Вы. AI-агент — native disabled button с пиктограммой и доступным именем; AI-вызовы и новый экран не добавлены.
- Версия Service Worker изменена на `pablicus-shell-input-nav-20260913-r1`, чтобы установленные клиенты получили новый комплект файлов через существующее сохранение и обновление.

Только восемь runtime-файлов: `app.js`, `chat.js`, `component-registry.js`, `index.html`, `message-menu.js`, `rich-composer.css`, `shell.css`, `sw.js`. Auth/Face ID, API, база, сообщения, хранилища и прототипы не изменены. В тестах скорректированы два прежних ожидания трёх вкладок/вложенности «Боты», заменённые прямым решением владельца.

## Проверка

- Исходный код: три нарушения после Enter подтверждены в каждом из двух движков.
- Исправленный код: Chrome 153 и WebKit 26.0 — по 48 PASS. Проверены 30 Enter, длинная вставка и сокращение текста, имитация уменьшения/смещения visual viewport и его возврата, явное раскрытие/сворачивание, черновик после Полотна и перезагрузки, одна отправка, навигация и размеры кнопок на ширинах 320/390/768/1280.
- Структурные контракты: 10 PASS. Финальные результаты — в `verification/`.
- Первый кандидатный прогон: Chrome не успел загрузить локальную страницу; WebKit прошёл геометрию, но тест отправки проверял эффект до завершения асинхронной отправки. Во втором прогоне тест ждёт подтверждённое изменение синтетического сервера, оба движка прошли. Проверки не ослаблялись до принятия отсутствующего эффекта.
- Обновление установленного кэша: 6 PASS. Старая опубликованная версия предложила обновление; после «Сохранить и обновить» активен новый кэш, видны пять вкладок, черновик сохранился. Квитанция Pages записывается после публикации.

Физическая клавиатура и плавность на iPhone владельца не проверялись удалённо. WebKit установлен в поддерживаемой данной macOS тестовой сборке; это не утверждение о совпадении с текущей версией iOS. Отчёты содержат только синтетические данные и геометрию; личные фотографии владельца в публичный репозиторий не включены.

Документация API, использованная при проверке координат: [VisualViewport.pageTop](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport/pageTop), [WebKit: поддержка Visual Viewport](https://webkit.org/blog/9674/new-webkit-features-in-safari-13/). Причина выше установлена локальным воспроизведением, а не перенесена из описания чужого бага.

## Критерии завершения

1. Ввод не прокручивает оболочку; Enter сохраняет перенос строки — проверено на текущем кандидате.
2. «Боты» снизу работает, AI-пиктограмма неактивна — проверено на текущем кандидате.
3. Обновление доступно по действующему URL — требует квитанции Pages и проверки опубликованных файлов.
4. Код, результаты, ограничение физической проверки и версия публикации записаны в Git — фиксация этого пакета.
5. Нет изменений вне указанного scope — проверяется allowlist diff перед публикацией.
