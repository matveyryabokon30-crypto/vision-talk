# Существующий публичный вход: проверка и снятое предложение UI

Статус: EXISTING_IMPLEMENTATION_CONFIRMED / PROPOSED_UI_TASK_NOT_STARTED.

WORK_START_HEAD: `ffde207`. Основание: прямое поручение владельца о простом открытом входе и регистрации. Исследование/план завершены отдельной Git-фиксацией; проверка не меняет утверждённый целевой дизайн и не закрывает остальные физические регрессии Block 2.

## Подтверждённая исходная точка

В Chrome 153.0.8010.36 на настоящем публичном домене создан новый тестовый аккаунт через WebAuthn virtual authenticator. Registration options/verify: 200; OAuth callback: 302; token/user/profiles/my_conversations_v3: 200. После возврата видны «Чаты / Дела / Вы», профиль `is_approved=true`, одна identity и один привязанный server subject. Это реальная серверная регистрация с виртуальным ключом, не физический Face ID. Тестовый ключ хранится локально с правами 0600 и не включается в Git.

На первом экране видна только «Войти с ключом доступа», создание аккаунта скрыто за ней. Публичный passkey скрывает всю почтовую форму существующих пользователей, даже если WebAuthn не поддерживается. Отдельный вход ведёт на страницу, начинающуюся с создания нового аккаунта. Это наблюдения для возможной отдельной проверки удобства; они не доказывают отсутствие регистрации. На первом экране также явно написано: «При первом входе укажите имя и создайте ключ доступа». После уточнения владельца изменение интерфейса не выполняется.

## Предлагавшаяся граница реализации — не начата

- Явные действия «Создать аккаунт» и «Войти с ключом доступа» на первом экране.
- Выбранное намерение управляет представлением следующей страницы; в обоих направлениях доступно переключение.
- Существующий вход по почте/паролю остаётся достижимым. Он не объявляется открытой email-регистрацией без квалифицированного SMTP.
- Неподдерживаемый WebAuthn, занятость, отмена и повтор имеют корректные состояния без ложного успеха.
- Сохраняются серверные права, правила trusted passkey activation, OAuth/PKCE, проверка origin и секреты flow. Массового одобрения профилей нет.
- Для публикации используется отдельный идентификатор выпуска и новое поколение существующего shell-cache; полноценная переработка Service Worker этой задачей не заявляется.

## Проверки для ранее предложенной UI-задачи — не выполнялись

Проверить два явных маршрута, неправильное/пустое имя, переключение режима, возвращение/повторный вход того же аккаунта, отмену, недоступный WebAuthn, доступность резервного входа, отсутствие дублей identity/profile, изоляцию собственных тестовых аккаунтов. Проверить опубликованные файлы на точном commit. Сохранить code/tested SHA, результаты и ограничения. Физическая проверка iPhone и полноценный публичный email-OTP отдельно не выдаются за выполненные. Предложение снято после уточнения владельца; это перечень возможных проверок, не отчёт об их выполнении.

Предложенная UI-задача не начата и не внедрена; runtime-файлы не изменены. Подтверждённая регистрация нового аккаунта сохраняется как дополнительная квалификация имеющейся системы.
