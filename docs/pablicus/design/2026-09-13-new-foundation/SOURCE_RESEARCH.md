# Основа новой оболочки Pablicus

## Codenotch: что исследовано и перенесено

Выбран именно [vinzdg/codenotch](https://github.com/vinzdg/codenotch), ранее названный в восстановленных решениях владельца. Исходный commit `bd62f4486a81a31e8239f79ae93f3370cb047b78`, MIT. Это нативный монитор использования AI-инструментов, не готовый мессенджер и не веб-фреймворк.

| Исходный файл | Существенная механика | Решение для Pablicus |
|---|---|---|
| `NotchPlacement.swift` | Координаты along/across; across всегда направлен внутрь экрана; одна модель для четырёх граней | Перенос `edgePoint()` в JS; рабочий контроллер использует левую/правую грань |
| `SideNotchShape.swift` | Единый контур, зеркальное преобразование; сначала ограничивается выпуклый угол, затем вогнутое сопряжение | Перенос формулы в SVG `notchPath()` с сохранением MIT notice |
| `NotchGeometry.swift` | Привязка к границе; ограничение положения видимой части; безопасный clamp даже при малом экране | Веб-панель ограничена областью содержимого, отдельно от заголовка, ввода и нижней навигации |
| `NotchLayout.swift` | Отдельные размеры тела/активной зоны/карточки; резерв высоты под содержимое | Раздельная геометрия кнопки и раскрытого меню, явные минимальные размеры; native-метрики не копируются целиком |
| `NotchMotion.swift` | Раскрытие/контент/скольжение/смена содержимого разделены; reduced motion отключает движение | В минимальной версии только короткое появление меню, 160 ms; reduced motion убирает анимацию. Пружинный reel остаётся отдельным проектированием |
| `NotchEdge.swift` | Направление раскрытия внутрь экрана; вертикальная/горизонтальная ось | Зеркальная левая/правая установка, выбираемая в настройках |
| Windows `notch.html` | Фиксированная панель, границы карточки, hover grace 250 ms, drag threshold, pointer cancel, сохранение DOM под указателем | Свой browser-контроллер: явное нажатие вместо обязательного hover; Pointer Events, Escape, стрелки; не заменяет основной контент при открытии меню |

Нативные AppKit/SwiftUI окна, экранные вырезы, Tauri `invoke/listen`, системный click-through, watchdog курсора и интеграции аккаунтов не включены в исполняемый веб-код. Их перенос в PWA был бы неправильным. В upstream-копии HTML эти вызовы сохранены как исследовательский оригинал; сам HTML не загружается прототипом.

Библиотека теперь содержит 8 исходных файлов Codenotch вместо первоначальных 5. В `library/pablicus-ui/` есть используемый, самостоятельный веб-адаптер. Прототип реально импортирует его как ES module. Побайтовое сравнение каждого оригинала с pinned Git object: [SOURCE_INTEGRITY.json](SOURCE_INTEGRITY.json).

## Figma и связанный код

Рабочая база конструктора — официальный [Simple Design System](https://github.com/figma/sds), commit `030aba021183cd5332b35c89c56fbaee5b600162`. Через подключённый Figma проверены компоненты, варианты, переменная Space/400 и текстовый стиль Body Base; из них создана редактируемая сборка. Это самостоятельный подтверждённый источник, не отождествление с роликом uiux.build.

В собственную библиотеку добавлены theme.css, JSON токенов/стилей, недостающий модуль генератора, исходники и Code Connect примеры Button/Tab/Navigation Button. Теперь 20 файлов с MIT notice и хешами. `foundation.css` **реально импортирует** vendored `theme.css`; радиусы и интервалы используются через SDS custom properties. Генератор запущен на изолированной копии с `--skip-rest-api`, без ключей и сети: результат побайтово равен сохранённому theme.css. [Проверка](TOKEN_BUILD.json).

React/React Aria компоненты изучены как образцы семантики, но не добавлены в статическую JS PWA как несовместимые зависимости. Для новой основы используются native buttons/links/forms. Перенос полноценной React/SDS-сборки не нужен для первого устойчивого цикла. MIT исходного кода не означает произвольные права на чужие товарные знаки, шрифты из видео или материалы Instagram; такие активы в прототип не включены.

## Контракт новой основы

1. Основные разделы Чаты / Дела / Боты / Вы доступны на телефоне снизу; на широком экране — слева. Боковой переключатель отвечает за представление внутри контекста, а не дублирует основные разделы.
2. В разговоре переключаются Разговор / Материалы / Дела. При открытии панели и смене представления геометрия `#workspace` не меняется; введённый текст сохраняется. Просмотр никогда не запускает AgentRun или применение AI-правки.
3. Старое Полотно и его сложный редактор не включены в прототип. Ввод сообщений — обычный textarea фиксированной высоты 72 CSS px с внутренней прокруткой. Enter добавляет строку, отправка — отдельная кнопка. Это новый минимальный контроль; старый composer не ремонтировался.
4. Подключены только локальные примеры: разговоры/заметки, добавление и завершение дел, поиск по содержимому, тема и положение панели. Ключ хранилища отдельный: `pablicus:next:prototype:v1`. Прототип явно сообщает о локальном режиме; серверные функции не подменены тестовыми ответами.
5. Установленный `pablicus/`, Face ID/passkey, Supabase, объекты, файлы и рабочие данные не изменены. Дальнейшее подключение должно идти через существующие контроллеры и domain-объекты, не через новую параллельную базу.

## Следующий один цикл

После просмотра владельцем этой основы: согласовать минимальную оболочку (расположение и состав навигации, роль edge picker, базовые поверхности). Затем отдельное задание — подключить **Чаты** к существующему состоянию/auth/транспорту, проверить на физическом iPhone, передать на независимую проверку через владельца и зафиксировать. После этого — следующий раздел по тем же правилам. Дела/Полотно/AI/социальный слой/фабрика из долгосрочного плана не исключаются.
