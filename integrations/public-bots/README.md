# Public Bots — отдельный кандидат интеграции, 0.1.0

Дата: 10 сентября 2026. Статус: **собран и проверен локально; не опубликован; main не изменён**.

## Что сделано

В полной копии актуального Public добавлены вход «Боты» в список чатов и «Мои боты» в профиль. Оба открывают один встроенный экран, без новой вкладки и отдельного входа. Основная навигация, логотип и иконки сохранены.

Экран включает создание закрытого бота из двух шаблонов, редактирование имени, описания, текстов и подписей кнопок, остановку/включение, настройку видимости с явным подтверждением каталога, переписку, восстановление серверной истории, новый диалог, просмотр и JSON-выгрузку заявок. Боты помечены как сценарные. ИИ, бронирование реального календаря, платежи, произвольный пользовательский код и внешние рассылки не добавлены.

Переписка открывается внутри Public, но данные бот-диалогов остаются в отдельном Bot Core. Бот ещё не представлен обычным участником общей таблицы messages/conversations. Внешние мессенджеры не используются.

## Исходная база

Актуальный main прочитан через GitHub: `daa313cf2c490bde210beb871e1845768522b044`.
Сборщик проверяет Git-хеши app.js, index.html, sw.js и входных модулей. При несовпадении он останавливается, а не перезаписывает новую разработку старым архивом. Имеющаяся локальная копия используется только после сверки соответствующих Git blob SHA с текущим GitHub.

Bot Core HTTP/service/flow в локальном стенде соответствуют исходникам ранее развёрнутой версии 0.1.1. Сервер в облаке и SQL этим этапом не меняются. Ранее принятые 76 облачных выполнений проверок остаются отдельной категорией доказательств.

Выход: `candidate-public/pablicus`, `candidate-public/public-bots.patch`, `candidate-public/BUILD.json`.

Повторная сборка в существующий выход запрещена: выберите новый `--out`.

В сгенерированной копии изменены 4 исходных файла: app.js (узкие точки подключения), index.html (два скрипта), sw.js (список публичных ресурсов и идентификатор кэша), ASSET_MANIFEST.json (пересчёт хешей). Добавлены 3 новых файла: bots-client.js, bots-panel.js, bots-panel.css. Остальной исходный интерфейс и авторизация копируются без изменений.

## Проверки этого этапа

- 17 Node-тестов клиента запросов: получение свежей сессии, ограниченный повтор после 401, смена аккаунта, отмена, ошибки, идентификаторы, отсутствие повторной POST-отправки после потери ответа.
- 3 Python-теста сборки: сохранность источника, точный состав изменения, проверка манифеста, отказ на изменённой базе, отсутствие публикации.
- 17 браузерных групп проверок на полном DOM и коде кандидата: создание двух ботов, чат, одна заявка после потери ответа/повтора, история, настройки сценария, stop/resume, мобильная ширина 390 px, обновление сессии, logout, разделение владельцев и отсутствие обычных chat-write RPC.

Браузерный стенд: Chromium about:blank; URL, Auth и хранилище исходящих заменены явными тестовыми реализациями. Сообщения обрабатывает настоящий локальный HTTP-сервис с BotService и SQLite. Это **не** новый облачный прогон, не реальная авторизация Supabase и не проверка установленной PWA. Навигация Chromium к localhost отклонена политикой среды; политика не отключалась и не обходилась. Скриншоты получены на этом стенде с синтетическими данными.

Для воспроизведения компонентного стенда нужны Python playwright 1.57.0 и доступный Chromium, затем:

```sh
node tests/bots/server.mjs
# В другом терминале после сборки:
python3 tests/bots/browser.py
```

Порт 8097, только loopback. Фикстуры используют вымышленные UUID и локальные тестовые обозначения сессий; облачных паролей/ключей нет. Перезапускайте сервер между прогонами для чистой SQLite :memory:.

## Сессии, исходящие и ограничения

Клиент ботов получает сессию у уже существующего Auth-клиента Public на каждом запросе. При 401 допускается одна проверка свежего токена/обновление через этот же клиент. Смена пользователя отменяет запросы и закрывает старый экран. Пароль или refresh token не копируются в модуль ботов.

Неподтверждённое отправленное сообщение перед HTTP-запросом записывается в отдельную IndexedDB `public-bot-outgoing-v1`, с привязкой к владельцу и диалогу. При отказе записи запрос не отправляется. Повтор использует прежние id/text/revision. Это не фоновая очередь: повтор требует действия пользователя. Набранный, но ещё не отправленный черновик хранится только в памяти текущей страницы. Автоматическое создание бота после неопределённой сетевой ошибки не повторяется, поскольку API создания бота не идемпотентен.

Нативная IndexedDB/Safari, реальное обновление сессии в Supabase, клавиатура iPhone, жизненный цикл установленной PWA, новая регистрация сервис-воркера, широкий аудит каталога и нагрузка **ещё не проверены в данной интеграции**. Эти пункты нельзя считать выполненными на основании локального стенда. При окончательном выпуске необходима проверка атомарной доставки shell-ресурсов и отката, чтобы не повторить старое смешивание версий.

## Допуск и следующий шаг

Не сливать и не публиковать рабочую PWA без отдельного подтверждения владельца. Не заменять существующий main целиком этим кандидатом. Перед любым выпуском вновь прочитать main, проверить хеши и возможную параллельную разработку.

Следующий шаг — развёртывание отдельного адреса предпросмотра с сохранением штатного маршрута авторизации; затем короткая пользовательская проверка создания/настройки/чата внутри интерфейса Public. Повторять прежние 76 проверок вручную целиком не требуется. Готовый производственный релиз не заявлен.
